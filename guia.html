02 · ALCANCE DE LA ENTREGA

Una base funcional creada como regalo

Información importante sobre la entrega, disponibilidad y continuidad del proyecto.

✦

Naturaleza del proyecto

Este sitio fue desarrollado de manera independiente como un regalo para Te Vi En Un Planetario, con la intención de aportar un espacio que refleje su identidad y permita acercar su proyecto a más personas.

Más que una entrega puntual, esta primera versión representa una base sólida sobre la cual el sitio podrá seguir creciendo con nuevas ideas, mejoras y funcionalidades conforme el proyecto continúe evolucionando.

◷

Compromiso y continuidad

El repositorio y la demostración pública permanecerán disponibles para que puedan consultarlos siempre que lo necesiten.

Mi intención es seguir acompañando este proyecto durante un tiempo indefinido, brindando apoyo, mantenimiento y mejoras cuando sea necesario. Si en algún momento existiera algún cambio importante en su disponibilidad, será comunicado con anticipación para garantizar una transición tranquila.

↓

Respaldo y conservación del proyecto

Como parte de la entrega se incluye una memoria USB con una copia íntegra del proyecto, que contiene el código fuente, recursos y archivos necesarios para conservar el sitio como un respaldo local e independiente de la publicación en línea.

Asimismo, el repositorio en GitHub permanecerá disponible para facilitar el acceso al historial de versiones y a futuras actualizaciones. De esta manera, el proyecto contará tanto con un respaldo físico como con una copia en línea para garantizar su conservación y continuidad.

Consideración sobre la publicación:

Durante el periodo de demostración, el repositorio es público. Esto significa que terceras personas o herramientas automatizadas pueden consultar o clonar sus archivos.

Hasta la fecha no se han detectado forks públicos, estrellas ni seguidores del repositorio. GitHub muestra actividad de clonación posiblemente automatizada, pero no proporciona información suficiente para identificar a las personas o herramientas responsables.

Decisiones posteriores:

Después de conocer la demostración, las responsables del proyecto podrán decidir si desean conservarla, elegir otro servicio de alojamiento, adquirir un dominio, contratar a una persona desarrolladora o ponerse en contacto con el autor para evaluar su continuidad.

Cualquier mantenimiento, ampliación, migración o nueva funcionalidad deberá acordarse posteriormente y de manera independiente.

03 · INSTALACIÓN

Instalar el sitio en una computadora

Elige el método que resulte más cómodo.

  1. Instala Git y Visual Studio Code.Hazlo solamente desde sus páginas oficiales.
  2. Abre una terminal en la carpeta donde guardarás el sitio.
  3. Clona el repositorio.
    git clone https://github.com/TeViEnUnPlanetario/tevienunplanetario.git
  4. Entra a la carpeta y selecciona la rama publicada.
    cd tevienunplanetario
    git switch trabajo-casa-footer-menu
  5. Abre la carpeta en VS Code e inicia Live Server.Prueba primero bienvenida.html y luego index.html.
  1. Abre el repositorio en GitHub.
  2. Presiona Code → Download ZIP.
  3. Descomprime el archivo y abre la carpeta en VS Code.
  4. Ejecuta Live Server.Este método sirve para consultar y probar. Para publicar cambios se recomienda Git.

05 · MANTENIMIENTO

Cambios frecuentes

Trabaja de uno en uno y revisa el resultado después de cada cambio.

Cambiar textos, fechas y enlaces +

Abre el archivo HTML correspondiente, busca el texto actual y reemplaza solamente su contenido. No borres los signos < y >.

Reemplazar una imagen +

Conserva una copia de la imagen anterior. Usa el mismo nombre y formato para evitar modificar el código, o actualiza exactamente la ruta indicada en src="...".

Actualizar un lanzamiento +

Revisa portada, nombre, descripción, fecha del contador y enlaces de preguardado. Pruébalo tanto en computadora como en teléfono.

Agregar una presentación +

Duplica únicamente una tarjeta completa existente y sustituye fecha, ciudad, recinto y enlace. Evita copiar secciones incompletas.

08 · AYUDA

Solución de problemas

GitHub Pages muestra una versión anterior +

Confirma que hiciste git push, revisa qué rama publica GitHub Pages, espera unos minutos y actualiza el navegador sin caché.

Live Server abre otra versión +

Verifica que VS Code tenga abierta la carpeta correcta y que la terminal indique la rama esperada con git branch --show-current.

Una imagen no aparece +

Comprueba mayúsculas, extensión y ruta. GitHub distingue entre Portada.jpg y portada.jpg.

Apareció un conflicto de Git +

No elijas todos los cambios automáticamente. Haz una copia de seguridad y solicita apoyo antes de completar el merge.
